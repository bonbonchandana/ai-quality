# Air Quality Prediction and Pollution Episode Detection

A virtual-sensor ML web app on the [UCI Air Quality dataset](https://archive.ics.uci.edu/dataset/360/air+quality)
(9,357 hourly records, Mar 2004 – Apr 2005). The model estimates the true CO concentration (mg/m³) at hour *t*
from five low-cost metal-oxide sensors, weather and earlier CO readings. It then flags hours where the observed CO
differs substantially from the estimate and labels each episode as an **unusual-pollution candidate** or a
**data-limitation candidate**, with the reason.

## Results (frozen model, chronological evaluation)

| Model | Validation MAE (3 folds) | Test MAE | Test RMSE | Test R² |
|---|---|---|---|---|
| **XGBoost (selected, trained on RTX GPU)** | **0.210** | **0.271** | **0.401** | **0.910** |
| Ridge | 0.244 | 0.252 | 0.353 | 0.931 |
| Linear Regression | 0.244 | 0.252 | 0.355 | 0.930 |
| Random Forest | 0.242 | 0.292 | 0.458 | 0.883 |
| KNN | 0.362 | 0.366 | 0.505 | 0.858 |
| Persistence baseline (previous hour) | 0.579 | 0.526 | 0.814 | 0.630 |
| Seasonal naive baseline (same hour yesterday) | 1.002 | 0.878 | 1.283 | 0.083 |
| Team notebook: Linear Regression (no lags) | 0.316 | 1.255 | 1.348 | −0.01 |

* The selected model is **48% more accurate than persistence** on the test period. Its 90% interval covered 91.8% of test hours.
* The model was **selected on validation only**. Ridge scored slightly better on test, but switching models after seeing test
  results would leak the test set, so the validation choice stands.
* An earlier version of this test period was inspected during exploratory research, so it is not a fully independent test.
* Episodes: 68 (35 unusual-pollution candidates, 33 data-limitation candidates). The labels come from transparent rules; causes are not verified.

All numbers are regenerated by `train_model.py` into `artifacts/`.

## Project structure

```
data/AirQualityUCI.csv    the dataset (original UCI file); train_model.py reads it from here first
train_model.py            steps 2–10: data, preprocessing, EDA, features, model selection, training, evaluation, tuning, saving
aq_features.py            shared feature engineering (imported by the saved pipeline)
air_quality_model.pkl     saved scikit-learn pipeline (imputer + scaler + XGBoost), created by train_model.py
main.py                   FastAPI app: GET /, GET /health, POST /predict, /api/* data, /dashboard
frontend/                 dashboard (HTML/CSS/JS + ECharts), served at /dashboard/
artifacts/                metrics, predictions, episodes, summary and cleaned hourly data
tests/test_api.py         pytest suite (endpoints, validation, 404/422, model reproducibility)
postman/                  Postman collection for the API
scripts/                  run_local.ps1 (local + network URL), public_url.ps1 (public URL)
research/, docs/          earlier research report, PRD and sources
```

## Run it

**Dataset:** put the original UCI `AirQualityUCI.csv` (`;`-separated, `,` decimals) in `data/`. If it's missing,
`train_model.py` falls back to `research/data/air-quality.zip`, and then to downloading the file from UCI.

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python train_model.py          # trains on the GPU if CUDA is available, otherwise on the CPU
.\.venv\Scripts\python -m uvicorn main:app --reload
```

* API root: http://127.0.0.1:8000
* Interactive docs: http://127.0.0.1:8000/docs
* Dashboard: http://127.0.0.1:8000/dashboard/

To get a URL for other devices on the same Wi-Fi, run `powershell -ExecutionPolicy Bypass -File scripts\run_local.ps1`. It prints the local and network URLs.

To get a temporary public URL:
1. Keep `scripts\run_local.ps1` running.
2. Install Cloudflare's tunnel tool once with `winget install --id Cloudflare.cloudflared`, then open a new terminal.
3. Run `powershell -ExecutionPolicy Bypass -File scripts\public_url.ps1`. It prints an `https://<random-words>.trycloudflare.com`
   address; add `/dashboard/` to the end and share it.

The link works only while both windows stay open, and you get a new address every time you start it.

## Test with Postman

1. Start the server from the project folder: `python -m uvicorn main:app --reload`. Wait for *Application startup complete*,
   and keep that terminal open.
2. Check it in a browser: http://127.0.0.1:8000 (root) and http://127.0.0.1:8000/docs (three endpoints).
3. In Postman, import `postman/AirQuality.postman_collection.json`, or create the request by hand:
   * Method: **POST**
   * URL: **http://127.0.0.1:8000/predict**
   * Body → **raw** → **JSON**:

```json
{
  "hour": 17, "weekday": 4,
  "pt08_s1_co": 1411, "pt08_s2_nmhc": 1191, "pt08_s3_nox": 519, "pt08_s4_no2": 1426, "pt08_s5_o3": 1920,
  "temperature": 13.4, "relative_humidity": 51.2, "absolute_humidity": 0.7808,
  "co_lag_1": 3.3, "co_lag_2": 3.0, "co_lag_3": 2.9, "co_lag_24": 4.5,
  "pt08_s1_co_prev": 1551, "pt08_s2_nmhc_prev": 1303, "pt08_s3_nox_prev": 469, "pt08_s4_no2_prev": 1520, "pt08_s5_o3_prev": 2171
}
```

4. Click **Send**. The expected status is 200 OK, with `"estimated_co_mg_m3": 3.3002`.

The response contains the CO estimate, a 90% interval and per-feature contributions (SHAP values). If you add
`"observed_co"` to the body, it also returns an anomaly verdict.

| Status | Meaning |
|---|---|
| 200 | Success |
| 404 | Wrong path, or unknown episode ID |
| 422 | Missing field, wrong type or value out of range (Pydantic validation) |
| 500 | Unexpected server error (details go to the server log only) |

Run the automated tests with `.\.venv\Scripts\python -m pytest -q`.

## The 16-step flow

| # | Step | Where |
|---|---|---|
| 1 | Problem definition | `train_model.py` header, dashboard About page |
| 2 | Data collection | UCI archive in `research/data/air-quality.zip` |
| 3 | Preprocessing | `-200` → missing, timestamp parsing, hourly grid (`train_model.py`) |
| 4 | EDA | `artifacts/clean_hourly.csv` + Data explorer page; `research/figures` |
| 5 | Feature engineering | `aq_features.py`: CO lags, previous-hour sensors, sensor deltas, cyclical time |
| 6 | Model selection | Linear, Ridge, KNN, Random Forest and XGBoost vs baselines and the team model, on 3 rolling folds |
| 7 | Training | Final pipeline trained on data before the calibration period (XGBoost on the CUDA GPU) |
| 8 | Evaluation | MAE/RMSE/R² on validation folds and a single frozen test pass; error by hour and month |
| 9 | Hyperparameter tuning | Grid search on the validation folds (XGBoost validation MAE 0.234 → 0.210) |
| 10 | Model saving | `air_quality_model.pkl` (joblib), reload checked against the original model |
| 11 | Backend | `main.py` (FastAPI + Pydantic) |
| 12 | Frontend | `frontend/` dashboard |
| 13 | Integration | The dashboard calls `/api/*` and `POST /predict` on the same server |
| 14 | Testing | `tests/test_api.py` (10 tests) and the Postman collection |
| 15 | Deployment | Uvicorn on `0.0.0.0:8000` via `scripts/run_local.ps1` |
| 16 | URL generation | Local, network and public (Cloudflare tunnel) URLs |
